# RTX release wrapper: prepublication gates and registry receipt

The [manifest](manifest.json) records the exact parent image, wrapper image,
registry digest, recipe revision, checkpoint revision, and lossless archive
hashes. Every `.gz` file decompresses to its original raw receipt bytes.
The cache seed manifest is preserved as metadata; compiled cache payloads are
inside the image and are not duplicated here.

The initially empty-cache wrapper passed prefix/xgrammar, image/audio, and all
80 reasoning API cases. The one-run seven-workload screen passed 6/7 contracts;
the fable had 133 words against the 140–170 requirement. Its timing is a
prepublication development screen, not the final benchmark table.

The version `ghcr.io/tpurtell/dots3-note-exl3-k4-rtx:20260925-v1` was pushed with
digest `sha256:2aff95d9896b3f3d3f8e3f4cfbaed90c77344d41d58fe7322eff9f4c73ec63b6`.
Authenticated digest pull passed. At this publication observation, package
visibility was private and anonymous pull failed with `unauthorized`. The
three registry logs preserve those outcomes. A subsequent visibility change
needs a separate anonymous-pull receipt.

Full qualification is running separately against the published digest with a
new runtime cache. These records do not mark release settings qualified or
establish final performance numbers.
